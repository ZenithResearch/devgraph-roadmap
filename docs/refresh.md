# Offline and live read-only refresh

The default build is offline; an explicitly configured local server also supports read-only live refresh. `npm run build` reads the existing frozen source files; it does not authenticate, mutate Devgraph, renew grants, apply workflow transitions, or contact providers.

For a later authorized refresh, use the supported owner CLI outside this browser/repository to perform only ordinary authenticated reads: query the Initiative, children, records, workflow state and dependency relationships. Credentials and native authority stay in the operator's existing owner-private environment. Do not put a token/key in configuration, JavaScript, query strings, exports, or browser storage. An expired/missing read grant is a limitation, not permission to use a status workaround or direct database access.

1. Save an immutable read packet outside the browser build and record exact command, read time, snapshot revision and success/errors. For multiple queries, verify one coherent revision or disclose inconsistency; do not blend partial reads into current canonical status.
2. Review and allowlist only canonical Work fields, containment, workflow facts and dependencies. Remove host configuration, transport credentials, private personal/provider data and unrelated runtime records. Preserve versions, archive flags and null fields. The process source format is `devgraph.work-export/v1`.
3. Save the new dated export as a new frozen input rather than overwriting historical evidence. Record original raw read-packet SHA, sanitized frozen-file SHA, capture time and the transformation in `examples/provenance.json`. A hash proves byte identity, not authority or canonical acceptance.
4. Refresh local implementation/review evidence independently, retaining its scope, date, artifact identity and limitations. Never treat tests or description notes as workflow transition receipts or production proof.
5. Update the configured paths/source IDs, then run `npm run check`. Compare exact counts, versions, status, archive, dependency edges, estimate coverage and token attribution with the read packet. Reconcile changes before trusting a projection. Review browser keyboard, narrow layout, source limitations and load failures again.

Zendo is a versioned repository projection that names Devgraph as authority; it is not claimed to be a fresh live canonical read. Its token attribution date is independent. The frozen process readback explicitly reports stale workflow progress and unqualified production. The observer cannot close either limitation.

The process evidence v1 format describes pending gate plans and supports only `production_ready: false`; it cannot carry a positive qualification claim or passed-gate receipt. Unsupported readiness upgrades or gate completion fields fail validation. A richer, reviewed input contract is required before such evidence can be projected. Canonical Task progress counts must agree with the individual workflow records. The separately dated `workflow_tracking_stale` hint can describe lag; a false hint alone does not establish a current/live snapshot. Zendo gate summaries follow its explicit Project gate statuses, which still cannot independently qualify production behavior.

## Opt-in live source

`ROADMAP_LIVE_CONFIG` selects an owner-private JSON file (`roadmap.local-live-config/v1`) containing `example_id`, the fixed installed `cli` path, a private `cache_dir`, and `repositories` with `id`, `label`, `path`, `expected_head`. The file is an operator configuration and is never copied into dist. It contains no credentials. Start the normal serve script with this variable to enable `GET /api/live/{example_id}`. HTTP only accepts its loopback Host and same-origin requests, with no mutation endpoint or CORS.

The API is `roadmap.live/v1`: source check/capture timestamps, refresh/error state, current normalized snapshot, gate plan, delivery evidence and public Git bindings. CLI stderr, private paths, host configuration and raw read packets are never returned. A capture checks matching complete100-record scoped workflow/version vectors before and after Work/hierarchy reads and two dependency passes. It accepts genuine workflow changes but refuses incomplete, inconsistent or out-of-scope reads. Complete raw packets are retained only in the private cache. A failed refresh leaves the last good normalized snapshot and shows stale status; it never publishes a partial current capture.

`roadmap.delivery-progress/v1` is a separate implementation-evidence contract. Its twelve current Process areas are not new Devgraph Work records. A validated area requires evidence and existing Project references. Unsupported states, duplicate IDs and private paths reject publication. Native issuance, direct installation, provider qualification and the pilot remain incomplete even after VM qualification is removed. Canonical writes remain pending if the current grant is inactive; this observer never changes authority to repair that condition.

## Milestone skill tree

Delivery milestones optionally accept `short_title` for compact node labels and `requires`, an array of unique existing milestone IDs. Omitting it preserves the prior input as independent roots. Dangling references and cycles are rejected. This is planned implementation sequencing, separate from the canonical Issue dependency graph and gate completion. The renderer groups nodes by prerequisite depth and draws branches; selecting a node reveals evidence and navigable prerequisites. Validated and partial evidence states remain unchanged. A pending node is ready to start only when all its prerequisites are locally validated; otherwise it needs prerequisites. Read-only refresh preserves selection and keyboard focus.

## Complete gate and milestone tree

The quest page projects every configured gate and every gate-specific Project milestone into one navigable skill tree. Milestone identity includes both gate and Project so repeated Project contributions remain separate. Solid local branches connect project contributions to each chest; dashed links preserve the canonical gate prerequisites without adding prerequisite gates from local evidence. Gate status alone awards chests. Selecting a milestone highlights its gate and opens its scoped Issue/Task details in the inspector. The wide tree scrolls within its own panel on narrow screens and offers a keyboard-accessible gate jump. The local implementation evidence path remains a separate supporting view beneath the canonical tree. No source schema migration or tracker mutation is required.

The complete tree opens in Fit all mode. Zoom controls, actual size, pointer-centered modifier-wheel/trackpad pinch and touch pinch adjust only the map. Drag its background to pan; Space-drag also works over nodes, and viewport-focused `+`/`-`, `0` (Fit all), `1` (actual size) and native arrow-key scrolling remain available. A gate jump opens that branch at readable scale. The bounded camera, current selection and pan position survive live refreshes; example switching starts a new fitted camera. Resize recomputes Fit all without resetting a manually chosen view.
